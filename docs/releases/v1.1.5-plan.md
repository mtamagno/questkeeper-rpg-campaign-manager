# QuestKeeper 1.1.5 - Storyforge release plan

**Release target:** Thursday, 29 October 2026

**Milestone:** [QuestKeeper 1.1.5 - Storyforge](https://github.com/mtamagno/questkeeper-rpg-campaign-manager/milestone/1)

Storyforge combines the four already-planned character-story days with the
complete 1.1.4 field-feedback backlog. The roadmap outcomes remain the spine of
each day; issues are attached where their architecture or user journey naturally
belongs instead of becoming a disconnected second queue.

## Release promise

By Thursday evening, a player can return to a character, understand how that
character changed, use their spells, abilities and resources at the table and
read the same evidence-linked story context for player characters and NPCs. A
Game Master can install, start, navigate, author and present that experience
without the currently reported setup, modal, preview, theme or large-screen
failures.

The tag is cut only when every issue in the milestone is closed with a merged PR
and **Resolved in version: 1.1.5** evidence. Epic issues close only after every
child acceptance contract passes.

## Delivery rules

- Keep one issue per commit and pull request. Do not hide unrelated fixes in a
  roadmap feature PR.
- Implement every `shared` issue in the public and production repositories in
  the same delivery cycle, with paired commits recorded in the sync ledger.
- Merge in dependency order. A parent epic is a release checklist, not a shortcut
  around its child issues.
- Run focused tests per PR. Run the complete public and production gates at the
  end of each day and again from clean release candidates on Thursday.
- Preserve manual workflows, legacy campaigns, private content boundaries and
  copyright/provenance rules. No issue is considered fixed only because its
  happy path works.
- Update issue metadata when merged, but close it only when the fix is present in
  the release candidate. Record `reported-in:1.1.4` and `resolved-in:1.1.5`.
- A release blocker discovered during verification pre-empts the next issue; it
  does not silently reduce acceptance criteria.

## Wednesday, 28 October - a rules-aware character toolkit

### Planned roadmap outcomes

1. Add a searchable spell and ability library per character.
2. Add prepared/favourite state, usage notes and trustworthy external references.

### Progress

- [x] The first roadmap outcome is implemented as a per-character projection
      over sheet-owned names and the existing local Compendium. Search, type filters,
      provenance labels and unresolved-entry fallbacks do not introduce a second
      rules model or bundled protected text.
- [ ] Prepared/favourite state, notes and references remain the second Day 11
      task. Issues #35-#37 still own the broader namespaced package platform and are
      not closed by this reader-only library.
- [x] Issue #35 establishes namespaced identity, provenance, explicit override
      precedence and fail-closed publication boundaries.
- [x] Issue #36 adds the reviewed SRD 5.2.1 source matrix, deterministic importer,
      visible attribution and a searchable bilingual baseline. Commercial books
      remain excluded and ORC candidates remain research-only.
- [ ] Issue #37 still owns private local package authoring, import/export and the
      update-safe user-owned workflow.

### Issue sequence

1. [#35 - license-safe compendium platform](https://github.com/mtamagno/questkeeper-rpg-campaign-manager/issues/35): establish source namespaces, provenance, precedence and export boundaries.
2. [#36 - redistributable baseline research](https://github.com/mtamagno/questkeeper-rpg-campaign-manager/issues/36): import nothing until the license matrix and automated guard approve it.
3. [#37 - local custom compendia](https://github.com/mtamagno/questkeeper-rpg-campaign-manager/issues/37): let users author/import private packages on the same namespaced contract.
4. [#26 - independent pronouns](https://github.com/mtamagno/questkeeper-rpg-campaign-manager/issues/26): complete the character presentation schema without inference.
5. [#27 - reviewed entity and batch translation](https://github.com/mtamagno/questkeeper-rpg-campaign-manager/issues/27): extend consent, provenance and stale-source review to the new character fields and references.

### End-of-day evidence

- Public builds contain only entries with approved, visible redistribution
  provenance; private packages are excluded by default.
- Search, prepared/favourite state, notes and references work without AI and do
  not overwrite user-owned compendium entries during updates.
- Translation batches are resumable and review-only; IDs, rules terms, media and
  cross-references remain stable.
- Pronouns are optional, language-aware and never inferred from names or images.

### Freeze and release sequence

1. **13:00 - feature freeze:** only acceptance fixes, documentation and release
   metadata after this point.
2. **13:00-15:00 - clean gates:** public `npm run verify`; production Manager,
   profiles, accessibility, offline, entity IDs, compendium provenance, strict
   TypeScript, both campaign builds and performance budgets.
3. **15:00-17:00 - release matrix:** source plus packaged Windows, macOS Intel,
   macOS Apple Silicon and Linux; fresh install, 1.1.4 migration, backup/restore,
   preview start/stop and clean shutdown.
4. **17:00-18:00 - visual matrix:** player and GM journeys at phone, tablet,
   1366x768, 1920x1080, 2560x1440 and ultrawide; light/dark/high-contrast,
   keyboard, screen reader and reduced motion.
5. **18:00 - candidate decision:** all milestone issues must be merged, marked
   `resolved-in:1.1.5` and backed by evidence. Otherwise the tag waits; no known
   data-loss, startup, privacy, accessibility or provenance defect is waived.
6. **After approval:** tag `v1.1.5`, publish **Storyforge**, attach native
   artifacts/checksums, update the release codex and verify both hosted demos.

## Explicitly not compressed

- No parent epic closes on architecture alone.
- No license uncertainty is converted into bundled rules text.
- No private campaign, transcript, credential or protected media enters the
  public repository.
- No AI-generated translation, relationship, mood or compendium entry publishes
  without review.
- No Thursday time pressure permits destructive migration or a release with a
  known primary-journey blocker.
